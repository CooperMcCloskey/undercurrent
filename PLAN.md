# Undercurrent: plan and status

This is a living document. Each workstream owner, and their agent, edits **only their own section** and ticks boxes as they go. New decisions are added as rows at the end of the decisions table.

## The pitch (30 seconds)

> Big geopolitical stories don't appear out of nowhere. They build up across local news, social media and Wikipedia before the mainstream notices. **Undercurrent** links all of that into stories, maps them on a globe, and predicts which ones are about to break. We backtested it against a momentum baseline, and here's a story it flagged a week early.

- **HRT** (*predictions and decision making*): an honest forecast with a baseline, calibration and no lookahead.
- **G-Research** (*make the invisible visible*): the build-up before a story breaks, shown on a globe.

### A: Ingest (owner: ____)

**Goal:** clean, resumable inputs for everyone else.
**Writes:** `data/raw/`, `data/processed/articles.parquet`, `wiki_*.parquet`, `bluesky/*.parquet`

  - `title`, taken from `<PAGE_TITLE>` in V2EXTRASXML
  - `locations`, with lat/lon and **FIPS→ISO2** country codes
  - `persons`, `orgs`, `themes`
  - `tone`
- [ ] Deduplicate articles (same URL; syndicated copies with the same title)
- [x] Wikipedia daily pageviews for given titles, cached → `wiki_pageviews.parquet` (`ingest/wiki.py`)
- [x] Wikipedia daily edit counts for given titles (revisions API) → `wiki_edits.parquet` (`ingest/wiki.py`)
- [x] Entity name → Wikipedia title resolver, cached (B and C both need it) (`ingest/wiki_resolve.py`)
- [x] Wikipedia daily top-1000 (bulk signal, bot-flagged) → `wiki_top.parquet` (`ingest/wiki_top.py`)
- [ ] Bluesky Jetstream consumer → `bluesky/*.parquet`, plus an in-process hook that D can use for `/api/live`
- [ ] (stretch) Reddit, only if API access was approved

**Needs from others:** none yet
**Notes:**
- Wikipedia: full guide in `pipeline/undercurrent/ingest/WIKIPEDIA.md`. Query on demand + disk cache, not dumps (dumps are about 42 GB for 60 days). After fetching, everything works offline.
- **8 languages** (en ja de fr ru es it zh, the most-read Wikipedias), linked by Wikidata ID. Start from `wiki_entity_daily.parquet`: one row per entity and day, languages summed, with per-language columns.
- **Wikimedia rate limit: 200 requests/min total, at most 3 at once** (new in 2026). About 5 s per entity (8 languages × pageviews + edits), so 1,000 entities take about 1.5 h. Pick entities carefully and start early.
- `wiki_top.parquet`: 8 languages × 60 days (2026-09-08..11-06) downloaded, with likely bots flagged (`suspect_bot`).

### B: Stories (owner: ____)

**Goal:** turn articles and posts into stable, sensible stories.
**Reads:** `articles.parquet`, `bluesky/*.parquet`. **Writes:** `data/processed/stories*`, and `data/export/` (snapshots and story details)

- [ ] Embed titles with `config.EMBEDDING_MODEL` in batches, cached to `data/processed/embeddings/` by article id

- [ ] Attach Bluesky/Reddit posts and Wikipedia pages to the nearest story centroid, with **a separate threshold per source**, calibrated by eyeballing about 50 pairs
- [ ] Exporter: write `meta.json`, `snapshots/<day>.json` and `stories/<id>.json` to `data/export/`, then run `uv run pytest`
- [ ] Point-in-time: stories as of day t use only data from day t or earlier (C depends on this)

### C: Forecast (owner: ____)

**Goal:** P(story volume doubles over the next 7 days), backtested honestly against momentum.
**Reads:** B's stories, A's Wikipedia tables. **Writes:** `forecast` and `outcome` in the snapshots, and `model` in `meta.json`

- [ ] Fix the label: `grew = volume(t+1..t+7) >= 2 × volume(t-6..t)` (`config.GROWTH_RATIO`), with a minimum-volume filter (for example ≥ 20 articles in the previous 7 days). Write the final definition in Notes
- [ ] Build labels with no lookahead: take the story's centroid at day t, and count future articles as the ones closest to that centroid
- [ ] Momentum baseline (`growth_7d`): AUC and Brier score
- [ ] Features:

  - number of distinct domains and countries
  - tone, and change in tone

## Decisions

| Decision | Why |
|---|---|
| Python pipeline + TypeScript web, one repo | The ML libraries are Python and the globe libraries are JavaScript |
| One Pydantic contract with generated TS types, and JSON export in API shape | Four people can work in parallel against mock data; shape drift is caught by pytest and tsc |
| Embed titles, not full article text | GDELT has no article text; scraping is slow and hits paywalls |
| Multilingual MiniLM embeddings (`config.EMBEDDING_MODEL`) | GDELT is multilingual; the model is fast on a laptop CPU |
| Cluster news first, then attach social posts with per-source thresholds | Threshold-linking everything chains unrelated stories together; posts and headlines don't sit in the same part of embedding space |
| Link Wikipedia by entity, not by embedding | Cleaner signal, and pageview/edit history is available |
| Social posts are for display only, not model features | There's no easy historical backfill, so they can't be backtested |
| scikit-learn gradient boosting rather than LightGBM | Avoids the libomp hassle on macOS |
| Reddit is a stretch goal | API access needs approval |
| Python 3.13 (pinned in `.python-version`) | 3.15 is too new to rely on for torch/faiss wheels |
| Heatmap of story footprints instead of one tower per story; custom heat layer instead of `heatmapsData` | Stories happen across regions, not at single points. The built-in heatmap layer is too slow to update for a time slider |
| Countries as one custom merged mesh, not `polygonsData` | 1,616 polygons meant ~4,800 draw calls per frame and a 3.7 s freeze at load; the merged mesh is 2 draw calls and builds in 60 ms |
